Terrafirma

Point it at a patch of land and get species-suitability maps — fused from real public geoscience data.

Domain Geospatial / ecology Stack Python · PostGIS · scikit-learn Role Solo architect & builder Started Mar 2026

Summary

Terrafirma models where a given species is likely to thrive. It ingests soil, terrain, climate, land-cover, and occurrence data from a stack of public sources, scores habitat suitability across the landscape, and renders the result as map tiles alongside an ecological interaction graph of the species around it.

Its defining feature is architectural: a strict two-layer split between a species-agnostic data plane and a species-specific inference layer. That seam keeps the geoscience reusable across any species and the modelling logic honest and independently testable.

Design & system architecture

Engineering highlights

Two-layer architecture

A species-agnostic data plane and a species-inference layer, joined by a one-way dependency verified by sweep — the reusable core stays clean as species accumulate.

Real geoscience, integrated

Seven-plus public sources — iNaturalist, SSURGO soils, USGS 3DEP elevation, PRISM climate, GLOBI interactions, GBIF, Mushroom Observer — normalised into typed providers.

Declarative, per-species configs

A single parser validates the whole species file; components are enable/disable-able by one YAML flag, so behaviour is data, not branching code.

Real modelling under the hood

A per-species RandomForest species-distribution model with pseudo-absence sampling, plus a NetworkX ecological interaction graph built from GLOBI.

484 tests & a "verify data first" gate

The suitability engine went from zero to 484 tests; a data-verification job checks that raster layers are present and physically plausible before anything scores.

Documentation that resists rot

A single source-of-truth codebase map, layered by volatility (stable intent vs. dated current state) — with an honest, dated verification readout rather than aspirational claims.

Showcase — challenges I overcame

1

Keeping the geoscience reusable across any species

Challenge
The naive build entangles "what a morel likes" with "how to read a soil raster." Every new species would then re-touch the data code, and the whole thing rots into a tangle.
Approach
I enforced a strict two-layer split: a species-agnostic data plane that serves typed geodata, and a species-inference layer that scores and fuses. The dependency points one way only — and I verify that seam by sweep, so a violation is caught mechanically.
Outcome
Adding a species never touches the data plane. The reusable core stays clean no matter how many species pile on top.
2

Fusing seven messy public datasets into one honest surface

Challenge
iNaturalist, SSURGO soils, USGS 3DEP, PRISM, GLOBI, GBIF, and Mushroom Observer disagree on projection, resolution, units, and completeness — and a suitability map built on a silently-broken layer looks perfectly plausible while being wrong.
Approach
I normalised each source into a typed provider, then added a "verify data first" gate that checks rasters are present and physically plausible before anything scores — and combined component scores in log-space with a geometric mean so no single layer can dominate.
Outcome
Bad inputs fail loudly at the gate instead of quietly poisoning the map, and the fused score stays balanced across components.
3

Proving the model instead of just claiming it

Challenge
Modelling code is easy to hand-wave. Without tests, a subtle regression in scoring or phenology hides for months, and documentation drifts into aspirational fiction.
Approach
I drove the suitability engine from zero to 484 tests, added a real RandomForest SDM with pseudo-absence sampling, and kept a single source-of-truth codebase map layered by volatility — with a dated, honest verification readout rather than claims.
Outcome
The engine is regression-guarded and the docs tell you what's actually true as of a date — the project can be trusted, not just demoed.
