Millwright

Let an AI author CNC toolpaths — without ever letting it drive the machine unsafely.

Domain CAM / CNC automation Stack Python · MCP · Fusion 360 API Role Solo architect & builder Started Jun 2026

Summary

Millwright is a bridge that lets a large language model author CAM operations directly in Autodesk Fusion 360 — recognising machinable features and generating toolpaths through the Model Context Protocol. It's the manufacturing-automation counterpart to my robotics work: applying agentic AI to a real machine tool.

The whole design is organised around one principle: the AI can plan, but it can never move the machine unsupervised. All motion stays gated behind a deterministic preflight and an explicit human arming step — a hard boundary the LLM path cannot cross.

Engineering highlights

Safety kept out of the AI path

Motion gating lives entirely in a deterministic preflight plus a human ARM step — never in the LLM-driven code — so an authoring mistake can't become machine motion.

A rigorous preflight

Tracks G90/G91 modal state, computes true arc bounding boxes, checks the work envelope, and warns on cutter-comp and unverifiable offsets before a job is allowed to run.

De-risked, transport-first

The full LLM→MCP→localhost→Fusion path was proven with a ping round-trip before any authoring tool shipped — the hard integration risk retired first.

Phased capability rollout

Feature recognition opens one class at a time — holes, then pockets, then contours — each gated on a real-part track record through the full build order.

Fail-safe execution

The run monitor drives the job over CNCjs with automatic feed-hold and stop on fault or a socket disconnect, rather than assuming a clean channel.

Clean secrets hygiene

No secrets in the repo: the bridge secret and CNCjs token are read from the environment via Doppler, with config kept git-ignored.
